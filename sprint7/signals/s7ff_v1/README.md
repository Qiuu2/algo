## 0. 给测试员：怎么用

标"**PM 拟**"的条目是本包新加的做法，要 CTO 过目同意后才算数。其余条目照远场单原文执行。

1. **文件在哪里**：`git pull` 之后就在 `wav/` 目录里，共 61 个 WAV 文件，另有一份清单 `MANIFEST.md5`。
   - **PM 拟**：拉完之后执行 `git status --short sprint7/signals/s7ff_v1`，结果应为空。不为空就停下，原样发回。
2. **文件名**形如 `s7ff_v1_<中心频率>Hz_<档>.wav`：

3. **播放设置**（开始前设一次，整个会话不改）：
   - 在笔记本的声音设置里，把输出设备的默认格式设为 **48000 Hz**（有 24 位就选 24 位）。

   - 笔记本的系统音量和播放器音量定好以后，整个会话都不动（远场单 §4.2"全程电平不变"）。电平只按 §4.2 调功放档位。

   - Leq 20 秒：在播放开始后 1.0–15.5 秒之间启动；
   - Leq 10 秒：在播放开始后 1.0–25.5 秒之间启动；
   - **PM 拟**：文件放完时 Leq 还没结束，就重放这个文件，重测这一个读数。
   - **PM 拟**：Leq 取 20 秒。这与远场单 §5"时长参考"一致，启动窗口有 14.5 秒，遥控或延时启动来得及（远场单 §3.3-2）。30 秒 Leq 也能用，但启动窗口只有 4.5 秒；如果要用 30 秒又嫌窗口太紧，请告诉 PM，换成更长的文件。

   - **PM 拟**：为了保持"全程电平不变"，切换时先**停止播放**（或把播放器静音），**不动**笔记本和功放的音量；切完以后从头重放文件。
   - 这一条请 CTO 过目时确认。
6. **电平与安全**：一律按远场单 §4.2、§0.5 执行（`V_FF_MAX`、功放从最小档起调、`g_m1_max_abs_sample` 不近满幅）。

   - **PM 拟**：文件两端有渐入渐出，**开始和停止播放时不应有咔哒声**；听到了就停下，原样发回。
   - 切表瞬间的轻微咔声，按切表执行单属于正常。

## 2. 规格出处与 PM 拟的选择（请 CTO 过目）

| 项 | 本包的做法 | 依据 / 理由 |
|---|---|---|
| 频带与边界 | 12 个名义中心（500 … 5000 Hz，另加 6300 Hz 栅瓣检查），带边 = 名义中心 × 2^(±1/6) | 远场单 §4.1 的带集。带边与 sprint7 仿真（`sprint7/sim/side30/fir/s7_fir_robust_design.py:297`）和驱动单（891–4490 Hz）同口径。**PM 拟**：与 IEC 61260 精确中心频率最多差 0.95%（1600 Hz 带，约 0.014 倍频程）[L3 解析计算]；侧抑 R = L(0°) − L(θ) 两边用同一个带，这个差在 R 里基本抵消 [L3] |
| 信号构造 | 周期性粉红多正弦：35 s 一个周期，带内每个 DFT 频点的幅度 ∝ f^(−1/2)，相位随机（每带固定种子），带外严格为零 | **PM 拟**。整周期内的谱形和带内能量是精确的，带外只剩 24-bit 取整噪声。它是周期性、确定性的信号，不是真随机噪声；但统计特性与高斯带噪相近：峰值因数 12.6–14.5 dB，Leq 窗口起伏见 §1。远场单 §4.1 只写了"逐带粉噪"，没有规定构造方法 |
| 电平 | 0 dB 档稳态 RMS −23.00 dB（以满幅为 0 dB） | **PM 拟**。远场单要求"同一数字 RMS"，没有规定数值。根据 critic 第 1 轮 M2，从 −20 降到了 −23，理由见下文"输入电平" |
| 位深 | 24-bit | **PM 拟**。如果用 16-bit，−40 dB 档的取整噪声相对带内能量约为 −38 dB，过不了 E1 ≤ −50 dB（反证 F6 实算 −38.4 dB） |
| 采样率 / 声道 | 48 kHz，单声道 | 板上音频采样率是 48 kHz（`sprint6/dsp/audio/m1_cces_project/src/m1_loopback_tdm.h:22`）[L1 源码]。板子只采 RX 的第 0 个 slot（同目录 `m1_loopback_tdm.c:13`、`:23`）[L1 源码]。单声道文件通常由播放软件复制到左右两路 [推断]，所以接哪一路都一样；§0 第 9 条的试放可以顺带确认这一点 |
| 时长 | 36 s，即 0.5 s 渐入 + 35 s 稳态 + 0.5 s 渐出 | 远场单 §4.1 要求"时长 ≥ Leq + 5 s"，§5 步 6 允许 Leq 10–30 s。**PM 拟**：按 30 s 上限设计。各种 Leq 长度的启动窗口见 §0 第 4 条 |
| 渐入渐出 | 0.5 s 升余弦 | **PM 加**：避免开始和停止时冲击喇叭、产生宽带咔哒。渐变段用的是同一周期信号的延续，由检查器 C 门把关 |
| 静音文件 | 1 个，全零，同一格式、同一时长 | **PM 加**：远场单 §4.4 写的是"播放器停 / 静音文件" |
| 带外规格本身 | 远场单 §4.1 原文：距带边一个倍频程以外 ≥ 50 dB；相邻带中心处 ≥ 30 dB | 原文标为 **[L4 暂定]，CTO / dsp 可改**。规格一改，就要重新生成并重新过门 |

**输入电平（板子这一侧）：PM 拟，待 CTO 定**

- **门限**：板子输入的余量线是 `0x49A00000` ≈ −4.8 dBFS。这条线是按半带滤波链最坏情况的增益（Σ|h| = 1.73）留的余量：输入在线以下，最坏情况也不会进入饱和；输入超过它，最坏情况的信号可能进入饱和（软削顶），往声学输出里加带外失真 [L3，`sprint4/dsp/core_only/src/tree_filterbank.h:38-40`]。另外，板测规则把"输入、输出都高"判为"音源太热，先降"（`sprint7/docs/S7_VERIFICATION_PLAN.md:53`），事后发现就要重测。
- **本包的余量**：最热的文件是 3150 Hz 的 0 dB 档，峰值 −8.49 dB。如果笔记本满幅正好对应板子满幅，它离余量线约 3.7 dB [L3 算术]。但这个对应关系取决于笔记本音量、笔记本输出电平和板上 ADC，**没有实测过**。
- **为什么要用最热的文件查**：各带峰值相差 1.95 dB，拿 1000 Hz 文件（−9.31 dB）去查，会比最热的文件少看 0.82 dB。
- **建议**：开测前，在本场要用的笔记本音量下，先重新 Load 一次（`g_m1_max_abs_sample` 只在初始化时清零，`m1_loopback_tdm.c:1199`），然后一次不间断地 Run，把 `s7ff_v1_3150Hz_0dB.wav` 完整放一遍，再读 `g_m1_max_abs_sample`（它记录的是清零以来的最大值，`m1_loopback_tdm.c:729`、`:748`）。读数要低于 `0x49A00000`，并留出 CTO 定的余量。这条检查要等 CTO 同意后才写进测试员的步骤。

**给 CTO 填 `V_FF_MAX` 时参考**

- **峰值因数**：本包文件的峰值因数是 12.6–14.5 dB，正弦是 3.0 dB。因此按万用表 Vrms 设到同一个 `V_FF_MAX` 时，本包信号的峰值电压比正弦高约 9.5–11.5 dB。
  - 板上每一路用的是与频率无关的单一权重（`m1_loopback_tdm.c:54`；切表执行单 §0："全频段单表"），所以功放输出端的峰值因数应与文件相近 [L3 推断，未实测]。
  - 这一点关系到峰值偏移（Xmax）和功放削顶。`V_FF_MAX` 取多少由 CTO 定。
- **万用表类型**：远场单 §4.2 只写了"万用表 AC 档"。平均值响应型（非真有效值）的万用表读本包信号会**偏低 1.03–1.08 dB** [L2 工具：按文件实算 mean|x|/RMS 换算]，实际驱动功率约比显示值大 27%。
  - **PM 拟**：用真有效值（True RMS）万用表设 `V_FF_MAX`。如果没有，请告诉 PM，我补一个同 RMS 的 1 kHz 正弦文件（远场单 §4.2 允许用正弦设）。

## 3. L 级与局限

- 本包的谱与指标是对交付文件字节的计算 **[L2 工具]**，用了三个工具，外加 critic 自己的独立复算：
  - Python 检查器 `s7ff_check.py`：不调用生成脚本，自己解析 WAV 字节；稳态段做精确 DFT，整个文件做 Welch 和连续性检查。
  - MATLAB 第二轨 `s7ff_xcheck.m`：用 audioread 读文件，自己做 fft，复算 RMS、峰值、E1、E2、P2 和衰减档残差。
  - ffprobe：读文件头。
- **这不是声学输出谱**。笔记本 DAC、板上 ADC 与 DSP、功放、喇叭都会改变实际放出来的声音。它们自己的带外成分和噪声不在本包的保证范围内，由远场单 §4.3 的 D_max 和 §4.4 的本底来体现。
- −40 dB 档的带外底是 24-bit 取整噪声，约为满幅以下 149 dB [L3 解析：2^−23/√12]。实际使用时，笔记本 DAC 和板上 ADC 的噪声会高得多 [L3 推断]，所以 −30 / −40 dB 档能读多深，由现场自检决定，不由文件决定。
- 方案 A / B 的 RTA 自带 1/3 倍频程滤波器，它的带边与本包名义带边的差，见 §2 第一行。

## 5. 交付方式：WAV 进 git（CTO 2026-10-02 选定）

- 测试员 `git pull` 即可拿到文件，git 本身保证文件完整；`git status` 干净，就说明文件没有被改过。
- **仓库体积**：WAV 原始约 302 MiB（316 MB），按 git 默认的 zlib 压缩实算约 257 MiB [L2 工具]。仓库会从现在的 24 MB 涨到约 0.28 GB，而且公开仓库的历史会永久保留这些文件。
- **以后再改的代价**：规格每改一次、重新生成一次，仓库又会多出约 0.26 GB。到时候可以再定是否改用 zip 另传。
- **`.gitattributes` 新增两行**：
  - `*.wav binary`：WAV 永远不做换行转换；
  - `sprint7/signals/**/MANIFEST.md5 -text`：清单在 Windows 上也保持 LF 换行，这样 §0 第 7 条里的 md5 在 Windows 上同样对得上。
